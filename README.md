# PHARITA / BABYMONSTER news bot

Бот собирает новости о Фарите и BABYMONSTER из нескольких источников,
отсеивает неважное и репосты, и публикует в Telegram-канал по заданному
шаблону — фото/видео + подпись с датой и ссылкой на источник.

## Что реально умеет бот (важно прочитать перед запуском)

Собрано **полностью бесплатно**, без единого платного API. Это значит,
что источники делятся на две группы по надёжности:

| Источник | Метод | Надёжность |
|---|---|---|
| Telegram-каналы | Telethon (свой юзер-аккаунт, официальный клиент) | ✅ Стабильно |
| YouTube | Data API v3 (официальный, бесплатный ключ) | ✅ Стабильно |
| Новостные сайты | Google News RSS + свои RSS-ленты | ✅ Стабильно |
| X (Twitter) | snscrape (неофициально) | ⚠️ Нестабильно — X агрессивно блокирует анонимный доступ, периодически может вообще переставать работать без вины бота |
| Instagram | instaloader (неофициально) | ⚠️ Средне — риск временных лимитов/блокировок аккаунта |
| TikTok | TikTokApi + Playwright (неофициально, требует ручного токена) | ⚠️ Наименее стабильно, выключено по умолчанию |
| Weverse | неофициальная библиотека (требует логин) | ⚠️ Экспериментально, выключено по умолчанию |

У X, Instagram, TikTok и Weverse просто нет бесплатных официальных API
для чтения чужих постов — платные варианты существуют (X API Basic/Pro и
т.п.), но раз бюджета на проект нет, тут выбран максимум возможного
бесплатно. Если один из "нестабильных" источников временно сломается —
остальные продолжат работать (ошибки одного источника не останавливают
остальные и не роняют бот).

## Формат публикуемого поста

```
➣ 📸 ┉ #<Категория>

• <Информация о новости>

Источник: <YouTube / Твиттер / Instagram / Weverse / Фото / Видео>

#PHARITA #BABYMONSTER ✮ @world_pharita
─── ⋆⋅☆⋅⋆ ─
```

Если у новости несколько фото — публикуются все (альбомом, до 10 штук —
лимит самого Telegram). Если есть видео — публикуется видео. Без медиа
пост **не публикуется** (по требованию задачи фото/видео обязательны).

## Никогда не копируем Telegram-посты дословно

Требование заказчика: контент, взятый из Telegram-каналов, нельзя
публиковать один в один — только пересказ своими словами. Логика в
`source_label.py` + `rewrite.py` + `admin_bot._ingest_item`:

- **Telegram-пост с текстом** → текст переписывается своими словами через
  Google Gemini (бесплатный уровень, `GEMINI_API_KEY`) перед публикацией.
  Если Gemini недоступен (нет ключа/кончилась квота/сбой сети) — публикуется
  исходный текст как временный компромисс, но в логах это видно явным
  предупреждением, это не должно происходить постоянно.
- **Telegram-пост только с медиа, без единого слова текста** → публикация
  **откладывается на `TELEGRAM_HOLD_MINUTES` (по умолчанию 90 минут)**. Всё
  это время бот ищет, не появилась ли за это время текстовая новость о том
  же (по времени) из другого источника (YouTube/Twitter/Instagram/Weverse/
  новости) — и если находит, использует этот текст вместо переписывания
  Telegram-поста. Если за `TELEGRAM_HOLD_MAX_MINUTES` (по умолчанию 120 минут)
  так и не нашлось ничего подходящего — публикуется просто с пометкой
  "Фото" или "Видео", без утверждений об источнике.

### Как подписывается источник
- Взято напрямую с YouTube/Twitter/Instagram/Weverse/TikTok — так и
  подписываем настоящей платформой.
- Взято из Telegram-канала, и в самом посте есть явное упоминание
  источника (например "Weverse") — подписываем этим источником.
- Взято из Telegram-канала без указания источника — по решению
  заказчика подписывается **"YouTube"** (это осознанное решение, не баг).
- Telegram-медиа без текста, для которого не нашли текст-донор — просто
  "Фото" или "Видео", без утверждения о платформе.

## Равномерная публикация в течение суток

Раньше бот публиковал все доступные посты пачкой в рамках одного цикла
опроса. Сейчас на день заранее генерируется набор случайных "временных
слотов" (по числу — дневной лимит) в `daily_slots.py`, и автопубликация
разрешена только тогда, когда время очередного слота уже наступило — это
даёт равномерный разброс 4-10 публикаций по всем суткам, а не подряд.

## Автопубликация, ручное управление и статистика

Бот — это не просто скрипт по расписанию, а интерактивный Telegram-бот
с меню на кнопках. Управлять им (см. `admin_bot.py`) может только аккаунт
с `ADMIN_CHAT_ID` из `.env` — у всех остальных кнопки не работают.

### Автопубликация со случайным дневным лимитом
Каждый день бот сам выбирает случайное число публикаций в диапазоне
`DAILY_POST_MIN`–`DAILY_POST_MAX` (по умолчанию 4–10) и постепенно
публикует столько важных новостей из очереди в течение суток — по мере
того, как источники их находят. Если подходящих новостей за день меньше
лимита, бот просто опубликует меньше (выдумывать контент он не будет).

### Меню (`/start` от админа один раз, дальше — кнопка)
После `/start` под полем ввода появляется постоянная кнопка **"🩷 Меню"**
(обычная Telegram-клавиатура, `ReplyKeyboardMarkup` с `is_persistent`) —
не нужно ничего печатать, просто тапнуть. Плюс команда `/menu` и значок
"/" рядом с полем ввода (через `setMyCommands`) работают так же.

- **🩷 Очередь (N)** — список найденных, но ещё не опубликованных
  автоматически новостей (с пометкой источника); на каждую есть кнопка
  "опубликовать сейчас". Ручная публикация не расходует дневной лимит.
- **💗 Статистика** — см. ниже.
- **🌸 Сводка за час** — то же самое, что и автоматическая часовая
  сводка (см. ниже), только по запросу.
- **🔄 Проверить источники сейчас** — запускает внеочередной опрос всех
  источников, не дожидаясь `POLL_INTERVAL_SECONDS`.

⚠️ Важное ограничение платформы: Telegram Bot API **не позволяет боту
задавать цвет кнопок** — это всегда решает тема оформления в приложении
самого пользователя, а не бот. Максимум, что можно сделать программно —
эмодзи в названиях кнопок (🩷💗🌸), что здесь и сделано; настоящего
розового фона на кнопках технически не бывает ни у одного Telegram-бота.

### Часовая сводка
Раз в час (`HOURLY_DIGEST_SECONDS`, по умолчанию 3600) админу приходит
сообщение со всем, что бот нашёл за этот час: по каждой находке — из
какого источника (Twitter/Instagram/YouTube/Weverse/Telegram-канал/
новостной сайт), короткий текст, есть ли фото/видео, ссылка и статус
(опубликовано автоматически / ждёт в очереди).

### Статистика — честно, без выдуманных цифр
Кнопка "Статистика" показывает **только то, что Telegram реально
предоставляет**:
- количество подписчиков канала (через Telethon-аккаунт, который читает
  каналы-источники — он должен быть добавлен в целевой канал);
- сколько пришло/ушло подписчиков сегодня (бот сам считает, пока работает,
  через `chat_member`-апдейты — для этого боту нужны права администратора
  канала);
- просмотры и реакции на сегодняшние посты;
- официальную расширенную статистику Telegram (% включённых уведомлений,
  лучший пост периода) — но она открывается автоматически только у
  каналов от ~500 подписчиков, существующих больше суток; пока условие не
  выполнено, бот честно об этом пишет.

**Принципиально не показываются** "заблокировавшие бота подписчики" и
"активные/неактивные подписчики" — таких данных не существует ни в одном
API Telegram, официальном или нет, их не видит даже владелец канала в
приложении. Бот прямо пишет об этом в статистике, а не подставляет нули
или выдуманные цифры.

## Установка

### 1. Python-зависимости

```bash
python -m venv venv
source venv/bin/activate       # Linux/macOS
# venv\Scripts\activate        # Windows
pip install -r requirements.txt
```

Если планируете включать TikTok-источник — дополнительно один раз:

```bash
python -m playwright install --with-deps chromium
```

### 2. Настройка `.env`

```bash
cp .env.example .env
```

Дальше заполняете по разделам:

#### Telegram — публикация
1. Создайте бота через [@BotFather](https://t.me/BotFather) → `/newbot` → получите `TELEGRAM_BOT_TOKEN`.
2. Добавьте бота **администратором** в канал `@world_pharita` (или другой целевой канал).
3. `TARGET_CHANNEL=@world_pharita`.
4. `ADMIN_CHAT_ID` — твой личный Telegram id (только у него будет доступ к кнопкам управления ботом). Напиши боту `/start` после первого запуска, чтобы открыть меню.

#### Telegram — чтение каналов-источников
1. Зайдите на https://my.telegram.org/apps, создайте приложение (бесплатно) → получите `api_id` и `api_hash`.
2. Впишите их в `TELEGRAM_API_ID` / `TELEGRAM_API_HASH`.
3. `SOURCE_TG_CHANNELS` — список username каналов о BABYMONSTER через запятую, без `@`.
4. Один раз выполните вход:
   ```bash
   python login_telethon.py
   ```
   Скрипт спросит номер телефона и код из Telegram (и пароль, если включена
   двухфакторка) прямо в консоли. После успеха создастся файл сессии
   (`TELETHON_SESSION_NAME`), и `main.py` будет им пользоваться без
   повторного входа. **Используйте отдельный номер/аккаунт, если не
   хотите использовать личный** — этот же аккаунт должен состоять в
   целевом канале (`TARGET_CHANNEL`), чтобы работала статистика.

#### YouTube
1. https://console.cloud.google.com/ → создать проект → включить "YouTube Data API v3" → создать API key (бесплатно, квоты достаточно с запасом).
2. `YOUTUBE_API_KEY=...`
3. `YOUTUBE_CHANNEL_ID` — ID официального канала BABYMONSTER (найти через просмотр исходного кода канала или сервисы вроде commentpicker.com/youtube-channel-id.php).

#### Переписывание текста из Telegram (Google Gemini)
1. Зайдите на https://aistudio.google.com/apikey (карта не нужна) → создать API-ключ.
2. `GEMINI_API_KEY=...`
3. Бесплатный уровень ограничен по числу запросов в минуту/день — для
   4-10 постов в сутки этого более чем достаточно.

#### Новостные сайты
Работает из коробки через Google News RSS — ключи не нужны. При желании
добавьте свои RSS-ленты через `NEWS_RSS_EXTRA_FEEDS` (через запятую).

#### X (Twitter)
Ничего настраивать не нужно, кроме `TWITTER_SEARCH_QUERIES`. Учтите
нестабильность (см. таблицу выше).

#### Instagram
1. `INSTAGRAM_PROFILES` — публичные аккаунты для мониторинга через запятую.
2. `INSTAGRAM_MOM_PROFILE` — публичный аккаунт мамы Фариты, если известен. Посты из него публикуются **всегда**, независимо от ключевых слов, с указанием источника.
3. `INSTAGRAM_LOGIN` / `INSTAGRAM_PASSWORD` — опционально, но рекомендуется для стабильности. **Заведите отдельный "запасной" Instagram-аккаунт для бота** — не используйте личный, есть риск временного ограничения аккаунта при автоматическом чтении.

#### TikTok (опционально, выключено по умолчанию)
1. Залогиньтесь в tiktok.com в браузере.
2. Через DevTools (F12 → Application/Storage → Cookies) скопируйте значение cookie `msToken`.
3. `TIKTOK_MS_TOKEN=...`, `ENABLE_TIKTOK_SOURCE=true`.
4. Токен периодически "протухает" — при сбоях источника обновите его тем же способом.

#### Weverse (опционально, выключено по умолчанию)
Требует `WEVERSE_EMAIL` / `WEVERSE_PASSWORD` фан-аккаунта, подписанного
на сообщество BABYMONSTER. Экспериментальная интеграция — при поломке
неофициальной библиотеки потребуется её обновление или замена.

### 3. Запуск (тест локально)

```bash
python login_telethon.py   # один раз, если ещё не входили
python main.py
```

Логи покажут, какие источники активны. Напиши боту `/start` в Telegram
(с аккаунта из `ADMIN_CHAT_ID`), чтобы открыть меню управления.

## Деплой на Render.com (бесплатный тариф — с оговорками)

Бесплатный тариф Render существует только для типа **Web Service** (для
Background Worker на Render вообще нет бесплатного плана). Web Service
обязан слушать HTTP-порт и получать запросы — иначе Render усыпляет его
примерно через 15 минут без входящего трафика. Поэтому в `main.py` есть
встроенный health-check сервер: отвечает `200 OK` на любой GET-запрос, но
сам по себе не мешает засыпанию — нужно, чтобы кто-то регулярно стучался
в него.

Также у Render free-инстансов **нет постоянного диска** — файлы (в т.ч.
файл сессии Telethon и SQLite-база) пропадают при каждом передеплое и
при периодическом пересоздании инстанса. Поэтому:
- сессия Telethon хранится в переменной окружения `TELETHON_SESSION_STRING`,
  а не в файле (получить — см. шаг 4 ниже);
- SQLite-база дедупликации/очереди/статистики при пересоздании инстанса
  сбросится — на бесплатном тарифе это ожидаемо и не критично для
  фан-канала, но если это станет проблемой, единственное решение —
  платный тариф с постоянным диском или вынос БД во внешний сервис.

### Шаги

1. Залейте проект в GitHub-репозиторий (без `.env` — он и так в `.gitignore`).
2. На [render.com](https://render.com): New → **Web Service** → подключите репозиторий.
3. Настройки:
   - Runtime: Python 3
   - Build Command: `pip install -r requirements.txt`
   - Start Command: `python main.py`
   - Instance Type: **Free**
4. Перед первым деплоем один раз локально выполните `python login_telethon.py`
   — в конце он напечатает длинную строку (session string). Скопируйте её.
5. В Render → Environment добавьте переменные (значения — из своего `.env`):
   `TELEGRAM_BOT_TOKEN`, `TARGET_CHANNEL`, `TELEGRAM_API_ID`, `TELEGRAM_API_HASH`,
   `TELETHON_SESSION_STRING` (из шага 4), `SOURCE_TG_CHANNELS`, `YOUTUBE_API_KEY`,
   `YOUTUBE_CHANNEL_ID`, `ADMIN_CHAT_ID`, `GEMINI_API_KEY`, и остальные по желанию
   (см. `.env.example`). `PORT` Render задаёт сам — трогать не нужно.
6. После деплоя Render даст публичный URL вида `https://ваш-сервис.onrender.com`
   — это адрес health-check сервера бота (не связан с Telegram API напрямую).
7. Чтобы сервис не засыпал, настройте бесплатный внешний пинг на этот URL
   каждые **10 минут**:
   - [UptimeRobot](https://uptimerobot.com) (бесплатно): New Monitor → HTTP(s) →
     вставьте URL из шага 6 → Monitoring Interval: 10 минут.
   - Либо [cron-job.org](https://cron-job.org) — аналогично.
8. Имейте в виду: даже с пингом бесплатный Render может пересоздавать
   инстанс раз в сутки и ограничивает суммарные часы работы в месяц — если
   нужна гарантированная стабильность 24/7, лучше платный тариф Render
   (от $7/мес, тип Background Worker — тогда диск и файл сессии тоже можно
   сделать постоянными) или VPS (см. ниже).

## Деплой на VPS

### Вариант А — systemd (без Docker)

```bash
sudo useradd -r -s /bin/false pharitabot
sudo mkdir -p /opt/pharita_news_bot /var/log/pharita_news_bot
sudo cp -r . /opt/pharita_news_bot
cd /opt/pharita_news_bot
sudo python3 -m venv venv
sudo ./venv/bin/pip install -r requirements.txt
sudo chown -R pharitabot:pharitabot /opt/pharita_news_bot /var/log/pharita_news_bot

# один раз — вход в Telegram-аккаунт для чтения каналов и статистики
sudo -u pharitabot /opt/pharita_news_bot/venv/bin/python /opt/pharita_news_bot/login_telethon.py

sudo cp deploy/pharita-bot.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now pharita-bot
sudo systemctl status pharita-bot
```

### Вариант Б — Docker

```bash
cd deploy
docker compose up -d --build
docker compose logs -f
```

Для первого логина Telethon в Docker выполните разово интерактивно:

```bash
docker compose run --rm pharita-bot python login_telethon.py
```
введите номер телефона и код, дождитесь "Успешно вошли как...", затем
переключитесь на обычный `docker compose up -d` — файл сессии сохранится
в volume.

## Как работает отбор "важных" новостей

Фильтрация — по ключевым словам (`filters.py`), без платных LLM:
- новость должна упоминать Pharita или BABYMONSTER;
- совпадение по теме (концерт, тур, фестиваль, интервью, реклама,
  камбэк, награда и т.п.) повышает приоритет;
- посты-шум (фан-арт, мемы, голосования, магазин мерча) без явной темы
  отбрасываются;
- посты с аккаунта мамы Фариты публикуются всегда.

Список ключевых слов легко расширить — правьте `PHARITA_KEYWORDS`,
`TOPIC_KEYWORDS`, `NOISE_KEYWORDS` в [filters.py](filters.py).

## Защита от повторных публикаций

`storage.py` хранит SQLite-базу (`data/seen_items.sqlite3`):
- по точному ID поста — не публикует один и тот же пост дважды;
- по текстовому "отпечатку" — не публикует одну и ту же новость дважды,
  даже если её независимо продублировали разные каналы/источники (окно
  30 дней).

## Дисклеймер

Скрейпинг X, Instagram, TikTok и Weverse ведётся через неофициальные
библиотеки в отсутствие бесплатных официальных API. Это может
противоречить условиям использования соответствующих платформ и не
гарантируется production-надёжным — платформы регулярно меняют защиту,
что может временно или постоянно ломать конкретный источник. Используйте
на свой риск, желательно на отдельных/некритичных аккаунтах.
